# 房源状态机设计

## 为什么需要状态机

维界的房源来源复杂：

- 屋主主动提交
- 房源顾问收集
- 微信群采集
- Telegram采集
- Facebook采集
- 小红书采集
- 租房网站爬虫

如果没有状态机，后期会出现：

- 未授权房源被公开
- 已出租房源仍然展示
- 重复房源无法合并
- 推广订单状态混乱
- 无法统计成交和转化

---

# 房源主状态

## raw

原始采集状态。

来源可能是：

- 爬虫
- 群消息
- 人工复制

特点：

- 未解析
- 未确认
- 不可公开展示

---

## parsed

已完成结构化解析。

已提取：

- 租金
- 房型
- 区域
- 邮编
- 联系方式
- 基础标签

但仍不可公开展示。

---

## pending_auth

等待屋主授权。

适用于：

- 非屋主主动提交
- 爬虫采集
- 顾问收集但未获得明确授权

---

## authorized

屋主已授权展示。

可以进入发布审核。

---

## published

已发布。

可在网站公开展示。

---

## promoted

推广中。

表示该房源购买了：

- 置顶
- 首页推荐
- 优选标签
- 小红书推广

---

## rented

已出租。

处理方式：

- 隐藏联系方式
- 保留历史数据
- 可展示为“已出租案例”

---

## archived

归档。

适用于：

- 长时间无人维护
- 房源过期
- 屋主失联

---

## rejected

拒绝展示。

原因包括：

- 疑似虚假房源
- 疑似中介冒充屋主
- 屋主不同意展示
- 信息明显不完整

---

# 状态流转

```text
raw
↓
parsed
↓
pending_auth
↓
authorized
↓
published
↓
promoted
↓
rented
↓
archived
```

也允许：

```text
published → rented
published → archived
pending_auth → rejected
parsed → rejected
```

# 状态权限

## raw

仅 admin / advisor 可见。

## parsed

仅内部可见。

## pending_auth

顾问可跟进授权。

## authorized

管理员可发布。

## published / promoted

公开可见。

## rented / archived

默认不在搜索结果展示。

# 状态变更记录

建议增加 `listing_status_logs`：

```sql
create table listing_status_logs (
  id uuid primary key default gen_random_uuid(),
  listing_id uuid references listings(id) on delete cascade,
  from_status text,
  to_status text,
  changed_by uuid references profiles(id) on delete set null,
  reason text,
  created_at timestamptz default now()
);
```

---

# 自动状态规则

建议规则：

- published 超过30天未更新 → 提醒屋主确认
- published 超过60天未确认 → archived
- promoted 到期 → published
- rented 超过90天 → archived
